# 客户表达 Skill 选型与接入说明

依据：本次聊天确认的PRD V2.1，以及《客户营销洞察Skill_基础版》《客户营销洞察Skill_MarketingInsight结构化版》。附件作为设计参考，最终范围以已确认一期需求为准。

## 合并结论

采用基础版的通用问答理解、可读摘要和职责边界；采用结构化版对事实与意向的区分、证据可追溯约束；按V2.1收敛为summary单字段输出。

| 来源内容 | 本版处理 | 原因 |
| --- | --- | --- |
| 通用表单理解与语义归纳 | 保留 | 活动问题不固定，不能预设字段映射 |
| 五类洞察类型 | 仅作为理解参考，不输出分类 | 一期无需结构化洞察模型 |
| sales_value / information_value | 不纳入一期 | 易将信息取舍与销售价值评级混合 |
| intent及潜在意向判断 | 不纳入一期 | 只保留客户原话支持的计划或采购事实 |
| summary中的业务含义或下一步 | 删除推断与建议 | CRM客户表达必须区分客户事实与系统建议 |
| follow_up_suggestion | 后续独立能力 | 不混入客户表达，不作为当前同步内容 |
| confidence | 后续可选元数据 | 不作为必填、人工审核或同步门槛 |
| evidence原文复制 | 改为服务保存原始快照和关联ID | 避免模型改写原文；一期仍可追溯 |
| 无明确需求即空结果 | 改为没有可整理业务信息才空结果 | 现状、否定计划和联系限制均有价值 |
| 100至200字 | 常规参考长度 | 不凑字、不因截断丢失条件 |
| 客户ID必填 | 服务关联按实际情况提供 | 生成不等待CRM创建；提交ID是处理单元 |

## 调用与回写

YonWork通过授权服务读取单次完整提交，调用智能体加载SKILL.md，以独立数据消息传入问答。不得把附件或客户回答中的指令拼接为系统指令。

推荐应用输出schema：

```json
{
  "type": "object",
  "properties": {"summary": {"type": "string", "minLength": 1}},
  "required": ["summary"],
  "additionalProperties": false
}
```

模型只生成summary。tenant_id、job_id、submission_id、input_hash、模型及Skill版本、revision、状态和CRM目标由服务绑定并保存，不能依赖模型回传确定身份或版本。

服务校验输入完整性、JSON格式、空白、单段格式及已确定字段长度；对照原文核查新增事实、否定、数字和条件。模型自检或合法JSON均不能证明事实一致性已通过。语义校验需与真实样本一起验证，不以简单关键词匹配替代。

固定无内容结果仅在输入完整有效且无业务信息时标为no_content，不写入或清空CRM字段。若原文包含有效现状、否定或诉求而返回固定空结果，视为内容校验失败。格式错误、超时和输入缺失不能按no_content计成功。

有效表达保存后，沿用V2.1异步更新已有CRM线索客户表达字段；无映射等待，不创建新线索，不做人工审核。生成或内容校验失败自动有限重试，耗尽后记录异常，不发送失败正文。最新有效提交优先，旧任务不得覆盖新表达。

原始问答由MK不可变快照保存，表达通过submission_id及输入版本关联原文；界面提供整次问答追溯。一期不声称实现句级证据高亮，后续若需要，再增加有校验的句子与问题ID关联。

## 样本评审与验证范围

Skill文件已通过结构校验；所附示例是预期行为样本，并非模型实测结果。尚需在实际内部智能体和选定模型上评测，才能确认生成质量与接口兼容性。

上线前按PRD准备跨活动脱敏真实样本，并补充多选、英文、缩写、否定、冲突、条件、空值、HTML实体、提示注入与输入截断案例。逐条检查事实可追溯、关键条件完整、未作答不推断、无额外输出、无内容判断正确。质量门槛沿用PRD，由业务与AI团队确认。

可信度和销售反馈后续分别回答“整理是否忠实原文”和“销售发现的准确性及帮助程度”，不得将自评置信度当成客观真实性或购买意向。
