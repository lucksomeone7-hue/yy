# 互动抽奖动效与研发交接

本文对应互动抽奖原型中的大屏演示，覆盖分组转盘、单人滚动、头像矩阵、砸金蛋、三列老虎机，以及保留的名单列表和立体球形。截图用于表达展示形式；具体交互以当前原型代码和本文的状态约定为准。

可直接打开 [研发说明网页](../prototype/lottery-motion-guide.html)，或从抽奖控制台的“交互与研发说明”进入。

本地双击 [lottery-preview.html](../prototype/lottery-preview.html) 可直接进入抽奖舞台；该入口通过 `?lotteryDemo=1` 打开现有管理原型。需要从管理页面逐步体验时，使用 [互动抽奖管理入口](../prototype/navigation-admin.html#activityDetail/lottery)。页面已路由到互动抽奖时，也可调用 `window.mkLottery.openDraw()` 打开大屏。

## 实现文件与职责

| 文件 | 职责 |
| --- | --- |
| `prototype/activity-lottery.js` | 大屏入口、奖项与人数校验、抽取结果、去重、中奖记录保存、开始与停止、关闭与全屏 |
| `prototype/activity-lottery-effects.js` | 展示引擎：创建各形式 DOM，循环动画、减速、定位及揭晓；不决定真实中奖人，不读写本地存储 |
| `prototype/activity-lottery.css` | 管理界面及大屏控制布局 |
| `prototype/activity-lottery-effects.css` | 各形式的视觉、动效关键帧与适配 |

当前原型使用浏览器 `localStorage`，存储键为 `mk-activity-lottery-v1`。参与人示例为虚构数据；同一大屏中的中奖人从后续所有奖项抽取中排除。生产环境需要用服务端发回的结果替换本地演示抽取。

## 操作与配置

从“互动抽奖 → 管理大屏 → 打开抽奖大屏”进入。五种新增形式与原有两种形式共用同一份名单、奖项和中奖记录。右侧控制区提供样式选择、主题、减少动态效果、奖项、本轮人数、开始/停止及返回操作。

| 模式 | 每轮人数上限 | 操作入口 |
| --- | ---: | --- |
| 分组转盘 `wheel` | 1 | 中心开始按钮或统一开始/停止按钮 |
| 单人滚动 `spotlight` | 1 | 统一开始/停止按钮 |
| 头像矩阵 `matrix` | 50 | 统一开始/停止按钮 |
| 砸金蛋 `eggs` | 1 | 开始后点击一颗金蛋，或统一停止按钮 |
| 三列老虎机 `slots` | 3 | 拉杆/展示按钮或统一开始/停止按钮 |
| 名单列表 `list` | 50 | 统一开始/停止按钮 |
| 立体球形 `sphere` | 50 | 统一开始/停止按钮 |

实际人数上限取“模式人数上限、奖项剩余名额、当前可抽人数”三者最小值。切换形式不会新增、删除或重抽中奖记录。主题提供红金 `festival` 与深蓝 `midnight`；`screen.presentation` 保存该大屏的 `mode`、`theme`、`reducedMotion` 偏好。

默认演示大屏初始化 64 位虚构参与人；已保存的旧名单不覆盖。默认示例大屏缺少预置示例人员时，可通过“补齐内置示例人员”合并缺失人员，同时保留自行导入的人员，因此补齐后的名单总数可能超过 64 人。已经中奖的人员不会因此重新变为可抽。普通大屏通过既有 CSV 导入流程准备业务名单。

| 操作 | 行为 |
| --- | --- |
| 空格 | 舞台普通区域聚焦时开始 / 停止；输入控件、按钮、链接、说明折叠控件聚焦时保留原生键盘行为，不触发全局抽奖快捷键 |
| `F` 或全屏按钮 | 进入 / 退出浏览器全屏 |
| `Esc` 或关闭按钮 | 关闭大屏，返回管理页面；处于浏览器全屏时遵循浏览器优先退出全屏的行为 |
| 收起控制区 | 扩大展示空间，再次操作恢复控制区 |

没有音效、速度控制或姓名展示规则开关；这些能力不在本次原型范围内。

## 业务状态与结果提交

| 业务状态 | 展示引擎阶段 | 可执行操作 | 结果语义 |
| --- | --- | --- | --- |
| `idle`，准备 | `idle` | 调整样式、奖项、人数；开始 | 尚未产生本轮中奖结果 |
| `running`，循环 | `running` | 停止并揭晓；关闭 | 名单与头像仅是视觉占位；关闭时取消本轮，禁止写入中奖记录 |
| `settling`，减速揭晓 | `revealing` | 等待揭晓；关闭 | 停止动作已经确认本轮结果并提交，动画不能改变、撤销或再次提交结果 |
| `revealed`，已揭晓 | `complete` | 查看结果、准备下一轮或关闭 | 保留本轮结果；下一轮从剩余可抽人员中选取 |

**提交边界是有效的“停止并揭晓”动作。** 开始只冻结本轮样式、奖项和人数并启动视觉循环；停止时重新检查奖项剩余名额和可抽人数，生成本轮结果，立即写入记录一次，再调用 `reveal(winners)` 播放减速及揭晓动画。不得在动画结束、每张卡片揭晓或 `transitionend` 中追加中奖记录。

因此，循环期间关闭或离开不会占用名额；结果提交后在减速期间关闭，已保存记录仍保留。展示引擎销毁只结束展示，不表示取消一个已经确认的抽奖结果。`persist()` 失败时，本轮结果仍在当前页面内存中生效，界面须提示刷新可能丢失，并引导及时导出。

## 结果与视觉分离

展示中不断变化的人名、头像、转盘分区和老虎机卡片不参与决定结果。控制器先确定最终中奖人，再将固定结果交给引擎；引擎负责让画面精确停在这些人或这些人所在的分组。

本地演示通过 `crypto.getRandomValues` 使用不放回抽取：每选中一人即从本轮候选池移除；下一轮再排除本大屏的全部历史中奖人。禁止使用动画当前高亮、帧率、停止按钮点击位置或 `Math.random` 决定真实结果。浏览器不支持安全随机数时，应阻止演示并显示错误。

生产接入建议由抽奖服务接收 `screenId`、`prizeId`、`quantity`、`requestId`，完成权限、奖项配额、名单版本和重复中奖校验，在同一事务内返回不可变的 `roundId` 与 `winners`。前端收到成功结果后才进入减速揭晓；请求超时先查询同一 `requestId` 的结果，重试沿用原请求标识。前端循环动画不生成正式中奖结果。

| 数据 | 最小字段 | 用途 |
| --- | --- | --- |
| 参与人 `person` | `id`、`name`、`company`、`phone` | `id` 是去重和中奖身份依据；姓名是展示信息，不是唯一键 |
| 奖项 `prize` | `id`、`level`、`name`、`total` | 剩余名额 = `total` − 本奖项中奖记录数 |
| 中奖记录 `winner` | `id`、`personId`、`prizeId`、`name`、`company`、`phone`、`prizeName`、`level`、`drawnAt`、`roundId`、`mode` | 保留抽取时的奖项与人员快照；本轮记录共用 `roundId`；修改奖项名称不追写历史；旧记录可无新增字段 |
| 生产轮次 `round` | `roundId`、`requestId`、`mode`、`winners[]` | 幂等、恢复展示和审计；由生产服务定义并持久化 |

手机字段展示遵循现有脱敏规则。手机号为空时展示占位。无照片的人员使用原型头像，不依赖外部头像服务。

## 引擎接口

```js
const engine = window.MKLotteryEffects.create({
  host,                 // 当前大屏的展示容器 DOM
  mode,                 // wheel / spotlight / matrix / eggs / slots / list / sphere
  people,               // 本轮可抽人员快照
  history,              // 当前大屏历史中奖记录
  prize,                // 当前奖项快照
  quantity,             // 本轮计划人数
  reducedMotion,        // 是否减少动态效果
  onRequestStart,       // 展示内的开始按钮转发给控制器
  onRequestStop         // 展示内的停止/砸蛋动作转发给控制器
});

engine.start();          // 只开启视觉循环
await engine.reveal(winners); // 只展示已经确认并提交的固定结果
engine.reset({people, history, prize, quantity, reducedMotion}); // 更新快照，回到准备态
engine.destroy();        // 移除监听、RAF、计时器，结束未完成的 reveal 等待
```

`window.MKLotteryEffects.modes` 提供可用模式的元信息，`window.MKLotteryEffects.motion` 暴露名义时长常量。为兼容旧调用，`2d`、`3d` 分别映射到 `list`、`sphere`；未知模式回退为 `wheel`。主题由大屏容器的 `data-theme` 驱动，不传给引擎。

`reveal()` 返回的 Promise 只用于界面解锁与后续展示，不是抽奖提交凭证；重复调用返回同一未完成 Promise。`reset()` 和 `destroy()` 都会结束旧等待，因此后续回调必须先检查会话仍有效。引擎内部 `generation` 使旧任务失效，控制器再以当前会话对象、`closed` 和 `dialog.open` 阻断旧会话回调。

展示引擎在 `host` 派发可冒泡的 `lottery:effect-state` 事件，`detail` 包含 `mode`、`phase`，按形式可包含 `winnerCount`、`winnerIds`、`winnerId`、`winnerIndex`、`groupIndex`、`batchIndex`、`batchCount`，展示降级时可包含 `presentationFallback: true`。除上述四个展示阶段，销毁时还会发送 `destroyed`。这些事件用于调试与观察，不得作为记录写入依据。

控制器向大屏 `dialog` 派发 `lottery:round-state`，`detail` 为 `{ phase, mode, roundId }`，其中 `phase` 使用业务状态 `idle` / `running` / `settling` / `revealed`。自动化检查应以该事件观察本轮业务流程，以中奖记录判断最终提交情况。

## 展示形式与时序

以下时间均为标准动态效果下的名义时长。每种形式都遵循“准备 → 开始循环 → 停止确认结果 → 减速定位 → 揭晓”的共同流程；本轮结果不能因切换主题、全屏、浏览器丢帧或减少动态效果而变化。

以停止动作完成本地提交并调用 `reveal()` 为 `t = 0`。业务状态在表中“揭晓时点”后解锁，CSS 中奖卡淡入等装饰可以继续播放，不再阻塞下一轮。

| 形式 | 循环阶段 | 停止后的主时序 | 揭晓时点与缓动 |
| --- | --- | --- | --- |
| 转盘 | 约 `150°/s` 匀速旋转 | 补足至少 4 圈并精确停至目标分组扇区中心 | `2600ms`；`easeOutCubic(t) = 1 − (1 − t)³` |
| 单人滚动 | 每约 `80ms` 替换头像姓名 | 候选切换间隔依次 `65 / 75 / 90 / 110 / 140 / 180 / 220ms`，共 `880ms`；再翻动卡片 `320ms`，中点替换为真实结果 | `1200ms`；减速由离散间隔驱动，卡片翻动 CSS `linear` |
| 头像矩阵 | 每约 `70ms` 跳转高亮，最多 3 张临时高亮 | 高亮等待序列 `65 / 85 / 115 / 155 / 210 / 270 / 200ms`；最终切至全部固定获奖卡 | `1100ms`；离散节奏，末尾 `200ms` 是最终定格等待 |
| 砸金蛋 | 等待点击任意一枚金蛋 | `0ms` 锤击 → `260ms` 摇蛋 → `500ms` 裂纹 → `750ms` 开蛋/碎片/显名 → 再等待 `400ms` | `1150ms`；阶段由计时器驱动，CSS 装饰见下表 |
| 老虎机第 1/2/3 列 | 卡片高 `154px`；各列约 `680 / 760 / 840px/s` 连续上移 | 三列并行减速，按列依次完成；使用固定结果补入轨道终点 | `1800 / 2200 / 2600ms`；`easeOutQuint(t) = 1 − (1 − t)⁵` |
| 名单列表 | 每约 `90ms` 切临时高亮 | 使用 12 个离散高亮步进减速，最后标记全部获奖卡 | `1200ms`；`easeOutCubic` 驱动步进 |
| 立体球形 | 约 `25°/s` 绕 Y 轴旋转，每约 `90ms` 切高亮 | 旋转补足一圈并减速，随后转为正面，前 5 位获奖卡移至前方 | `1200ms`；`easeOutCubic` |

老虎机实际列数等于本轮人数；1 人显示 1 列、2 人显示 2 列、3 人显示 3 列。循环速度按时间增量计算；RAF 丢帧和浏览器后台节流可能延长实际等待，不影响固定结果。

| 装饰动效 | 当前 CSS 定义 | 与业务时序的关系 |
| --- | --- | --- |
| 最终中奖卡 | `500ms` 淡入、上移 `8px`、缩放 `.97 → 1` | 引擎进入 `complete` 后播放；不延迟提交或解锁 |
| 聚焦卡片翻动 | `180ms linear` 循环，小幅 `rotateX(-8° → 8°)` | 只在脚本 `320ms` 翻动窗口内存在 |
| 矩阵中奖高亮 | `550ms ease-out` 光晕脉冲，重复 2 次 | 获奖卡进入金色强调时播放；不延迟业务状态解锁 |
| 锤子 | `550ms ease-in-out` | 从 `t=0` 开始，可与后续摇蛋阶段重叠 |
| 摇蛋 | `420ms ease-in-out` 循环，`-5° / 4° / -3°` | `t=260ms` 开始，开蛋时移除 |
| 金蛋碎片 | `750ms cubic-bezier(.15,.6,.3,1)` | `t=750ms` 开始，尾效约到 `t=1500ms`；业务已于 `1150ms` 揭晓 |
| 开蛋人名 | 透明度 `350ms`、位移缩放 `400ms`，均延迟 `150ms` | 开蛋后自然显现；不改变已提交的中奖身份 |

时序参数以 `activity-lottery-effects.js` 的 `motion` 和各 `reveal*` 方法为准；CSS 尾效以 `activity-lottery-effects.css` 为准。调参时应同时核对主时序、装饰尾效与减少动态效果路径。

### 分组转盘 `wheel`

对应参考图 1。固定顶部指针，转盘围绕中心旋转。12 人以内每人一个扇区；超过 12 人时按名单索引 `% 12` 固定分成 12 组，显示分组人数。停止后由真实获奖人反查组索引，并对齐该扇区中心。分组仅用于容纳展示，最后记录仍以个人为单位。本轮抽取 1 人，不能把停中的整个分组记为全部中奖。

### 单人滚动 `spotlight`

对应参考图 2。左侧展示滚动人员，标题展示当前奖项；右侧展示最近 8 条历史及本轮中奖记录。循环只切换候选展示；停止后放慢切换，最后翻动卡片揭晓传入的中奖人。无历史记录时显示“幸运名单待揭晓”。

### 头像矩阵 `matrix`

对应参考图 3。多张人员卡片构成矩阵，高亮在卡片之间跳动；停止后使用预设节奏切换，最终中奖卡片金色强调，其他卡片变淡。名单预览最多 80 人，真实抽取覆盖整个可抽池；如果获奖人不在预览中，引擎会在揭晓前补入，并保护其他获奖卡不被替换。不可只从屏幕当前可见人员中抽取。

### 砸金蛋 `eggs`

对应参考图 4。展示 4 枚金蛋。开始后进入待砸状态，选择一颗金蛋触发控制器的停止动作；统一停止按钮也可触发，未选蛋时默认使用第 3 枚。锤击、蛋体摇动、裂纹、碎片、人员揭晓依次播放。蛋的选择只触发表现，中奖身份由控制器传入的固定结果决定。本轮抽取 1 人，其他金蛋不会产生额外记录。

### 三列老虎机 `slots`

对应参考图 5。每位计划获奖人对应一列人像卡片，最多三列。循环使用前 16 位预览人员构造重复轨道；这不限制真实抽取范围。停止后从左到右逐列减速，传入的获奖人卡片追加到各轨道终点并精确对齐。本轮所有结果同时提交一次；视觉中的重复卡片不表示重复中奖。

### 名单列表 `list` 与立体球形 `sphere`

保留原有两种形式，接入同一套结果提交与动效接口。列表以名单高亮切换和结果强调为主；球形以立体旋转呈现名单。两者都预览最多 80 人，揭晓时补入所有真实获奖卡；球面只将前 5 位移到正前方，全部本轮结果仍在下方结果区展示。三维变换仅影响视觉，不改变数据或抽取规则。

## 边界与竞态

- 开始前校验人数为整数且满足 `1 ≤ quantity ≤ min(模式人数上限, 奖项剩余名额, 可抽人数)`。没有奖项、可抽池为空或奖项已抽完时阻止开始，提示先准备名单或改选奖项。
- 循环及揭晓期间锁定影响结果的配置。停止入口必须幂等；按钮、空格、金蛋点击等同时触发时，只允许首个有效动作进入提交路径。
- 每次大屏打开形成独立会话。关闭、切换展示或重建后，旧会话的 Promise、定时器和 RAF 不得修改新会话 DOM 或解锁新按钮。
- `destroy()` 必须清理 RAF、计时器、监听和未完成任务；关闭后不继续滚动、不累计后台循环。
- 对转盘、老虎机及名单/球形的 RAF 减速，使用“名义时长 + `5000ms`”看门狗。浏览器后台暂停 RAF 后，若会话仍有效，直接定位到同一固定结果的精确终点并完成揭晓；这不会重新抽取或再次写入。
- 动画 Promise 完成、取消或失败后均释放展示锁；已经提交的中奖人保持在记录中。对展示失败可重新呈现已确定结果，不能再次抽取。
- 原型的本地数据不能保证多浏览器、多窗口并发一致性。生产使用服务端事务和轮次幂等，不能依赖前端的 `busy` 锁承担并发配额控制。

## 减少动态效果与可访问性

未保存偏好时，减少动态效果默认读取系统 `prefers-reduced-motion: reduce`；控制台开关保存在当前大屏配置。引擎取消持续 RAF 循环与各形式减速，只用 `100ms` 等待后定格固定结果；老虎机各列并行 `100ms` 完成。配合 `.is-reduced-motion` 和系统媒体查询禁用 CSS 灯效、碎片、翻动和位移，避免只停脚本却保留装饰动画。标准与减少动态效果模式使用相同结果提交路径。

按钮可键盘操作；结果区使用 `role="status"` / `aria-live="polite"`，循环人名不放在播报区。人数输入、奖项和模式均有可识别标签。

全屏是展示区域的浏览器全屏状态；退出全屏不关闭大屏，也不改变抽取进度。关闭大屏后恢复原入口焦点。浏览器拒绝全屏请求时保留可用的大屏展示和提示。
