## 1. 背景与目标

现有短信模块能够完成模板选择、发送对象选择、立即/定时发送、发送记录和模板管理等基础操作，但在列表检索、数据归属、模板选择效率、人群规模反馈、定时时间校验和发送前风险确认方面存在不足。

本次改造目标如下：

1. 提高短信记录和模板的查找效率。
2. 明确短信、模板的发布人及组织归属。
3. 在发送前准确展示目标人群规模。
4. 阻止历史时间进入定时任务。
5. 减少误发、重复发送的风险。
6. 统一字段名称、错误提示和列表交互。

## 2. 范围说明

### 2.1 本期范围

- 短信管理列表的发布范围筛选及模板标题搜索。
- 去除已发送列表中的“重命名”。
- 短信模板列表的信息展示和搜索。
- 发送短信时的模板搜索、模板元信息展示和内容预览。
- 分组、标签的人数展示、空人群禁用和。
- 定时发送的历史日期、历史时间禁用及提交校验。
- 发送前确认页。
- 已发现问题的修复和交互优化。

### 2.2 不在本期直接定论的范围

以下能力在探索测试中未完成真实链路验证，需要研发联调环境或测试号码后单独验收：

- 真实短信下发、扣费和运营商送达回执。
- 模板提交到第三方供应商后的完整审核链路。
- 定时任务到时执行、失败重试和补偿。
- 大规模号码去重、无效号码和国际号码的真实处理。
- 统计导出及失败明细下载。

## 3. 名词与业务口径

| 名词 | 口径 |
|---|---|
| 本人发布 | `creatorId` 等于当前登录用户的记录。 |
| 所在组织发布 | `creatorOrgId` 等于当前用户所属组织的记录；包含本人发布。 |
| 其他组织发布 | `creatorOrgId` 不等于当前用户所属组织的记录。 |
| 模板标题 | 短信模板供业务人员识别和搜索的名称；全模块统一使用该名称。 |


| 历史时间 | 小于或等于服务端当前时间的时间点。 |
| 系统时区 | 默认北京时间 `Asia/Shanghai`（UTC+8），前后端及页面提示保持一致。 |

## 4. 功能需求

### 4.1 短信管理列表

#### 4.1.1 发布范围筛选

列表顶部增加以下筛选项：

- 全部。
- 本人发布。
- 所在组织发布。
- 其他组织发布。

交互要求：

1. 单选切换，默认选中“全部”。
2. “所在组织发布”包含本人发布。
3. 每个筛选项可展示当前条件下的记录数量。
4. 切换发布范围后回到第 1 页。
5. 发布范围与模板标题、短信类型、发送状态等筛选条件取交集。
6. 权限控制由服务端完成，前端筛选不得突破用户的数据权限。

#### 4.1.2 搜索

搜索框支持按短信模板标题查询。

验收要求：

- 支持完整标题和部分标题。
- 自动去除查询词首尾空格。
- 中文、英文、数字均可搜索；英文大小写不敏感。
- 点击搜索或按 Enter 均可触发。
- 无结果时显示空状态和“清空筛选”操作。
- 重置后恢复默认条件、返回第 1 页并重新加载。

建议接口参数：

```text
templateTitle: string
publisherScope: all | mine | current_org | other_org
smsType: all | notice | promotion | international_notice
sendStatus: sent | scheduled
page: number
pageSize: number
```

#### 4.1.3 列表展示与操作

建议字段顺序：

1. 模板标题
2. 短信类型。
4. 发布人 / 所属组织。
6. 创建时间。


交互要求：

- 短信正文默认展示两行摘要，支持“查看全文”。
- 已发送列表操作保留“统计、删除、再次发送”，去掉“重命名”。
- 定时发送列表至少提供“详情、取消定时”；
- 删除和取消定时必须二次确认。
- 列表分页显示条数必须与请求的 `pageSize` 一致。
- 模板编码应使用面向业务的统一编码；内部主键不应混入同名字段。

### 4.2 短信模板列表

#### 4.2.1 列表字段

模板列表需显示：

- 模板编码。
- 短信类型。
- 模板标题。
- 短信内容摘要。
- 短信签名。
- 创建人。
- 所属组织。
- 审核状态。
- 创建时间。
- 操作。

模板正文默认折叠为摘要，避免长正文造成单行过高。

#### 4.2.2 模板搜索

- 支持按模板标题搜索。
- 可与短信类型、发布范围、审核状态组合筛选。
- 只在用户有权查看的模板范围内查询。
- 无结果时提供清空条件入口。

#### 4.2.3 模板操作

- 审核通过或审核中的模板若不允许直接编辑，需展示禁用原因。
- 建议提供“复制为新模板”，复制标题自动增加“（副本）”。
- 审核状态需展示提交时间和最近同步时间；超出正常审核时长时提供处理入口。

### 4.3 发送短信——模板选择

模板选择器改为可搜索的列表或弹层，不使用只显示标题的超长普通下拉框。

每个模板选项至少显示：

- 模板标题。
- 模板类型。
- 短信签名。
- 创建人。
- 创建时间。

交互要求：

1. 支持按模板标题实时搜索或提交搜索。
2. 默认只返回“审核通过”且当前用户有使用权限的模板。
3. 选中后展示完整短信内容、创建人和创建时间。
4. 没有匹配模板时说明原因并提供前往模板管理的入口。


建议返回字段：

```json
{
  "templateId": "string",
  "templateCode": "string",
  "templateTitle": "string",
  "smsType": "notice",
  "signature": "用友网络",
  "content": "string",
  "creatorId": "string",
  "creatorName": "string",
  "creatorOrgId": "string",
  "creatorOrgName": "string",
  "createdAt": "2026-09-09T09:30:00+08:00",
  "reviewStatus": "approved"
}
```

### 4.4 发送对象——分组和标签

#### 4.4.1 展示要求

每个分组和标签显示名称及当前有效人数，例如“认证答辩通知组（128人）”。

- 人数大于 0：正常展示并可选择。
- 人数等于 0：整体置灰、复选框禁用，提示“暂无成员，不可选择”。
- 支持按分组或标签名称搜索。
- 人数应基于发送权限范围内、具备可用手机号的当前成员动态计算。



### 4.5 定时发送

#### 4.5.1 页面限制

- 日期组件禁用今天之前的日期。
- 当选择今天时，禁用当前时刻及之前的时间。
- 时间粒度建议为 15 分钟。
- 页面明确显示“北京时间（UTC+8）”。
- 切换回立即发送后，定时字段不参与必填校验。

#### 4.5.2 双重校验

前端在以下节点校验：

1. 选择日期和时间时。
2. 点击“预览并确认”时。
3. 最终确认时，防止页面停留后原时间已过期。

服务端必须再次以服务端时间校验：

```text
scheduledAt > serverNow
```

历史时间应返回明确业务错误，例如：

```json
{
  "code": "SMS_SCHEDULE_TIME_EXPIRED",
  "message": "发送时间必须晚于当前时间，请重新选择"
}
```

建议增加最小提前量，例如定时任务至少晚于当前时间 5 分钟，具体数值由任务调度能力确认。

### 4.6 发送前确认

点击“预览并确认”后展示：

- 模板标题、短信类型和短信签名。
- 完整短信内容及变量替换结果。
- 已选分组和标签。
- 去重后有效手机号数量、无效手机号数量。
- 发送方式及时间。
- 单人短信分段数、总计费条数和预计费用。

若用户返回修改，应保留已选择的模板、人群和时间。

## 8. 非功能要求

- 前端所有禁用状态必须有视觉差异，并保留可理解的原因说明。
- 表单控件支持键盘操作，搜索框可按 Enter 提交。
- 搜索、筛选和人群估算应有加载、空数据和失败状态。
- 列表接口及模板搜索建议在正常数据量下 2 秒内返回。
- 人群估算和最终发送使用相同的数据权限及手机号有效性口径。
- 所有发送、定时、取消、删除和再次发送操作写入审计日志。
- 服务端不得依赖前端传入的人数、费用和时间有效性结论。

## 9. 研发待确认项

1. “所在组织”是否仅指当前一级组织。
3. 0人判断是否只统计有可用手机号。
4. 模板标题搜索使用包含匹配。
5. 定时发送的最小提前量、最大可预约时间和任务调度时区。
6. 模板审核中超过多久认定为异常，异常由哪个系统或角色处理。（暂不处理-通信云的规则）

8. 删除是逻辑删除还是物理删除，是否提供恢复能力。
9. 定时任务是否允许修改；若允许，执行前多少时间停止修改。

## 10. 原型与实现说明

当前线上原型已实现并验证以下交互：

- 已发送列表去掉“重命名”。
- 本人发布、所在组织发布、其他组织发布筛选。
- 短信模板标题搜索、筛选重置、分页和空结果状态。
- 模板搜索及创建人、创建时间展示。
- 分组和标签人数展示，0人选项禁用。
- 历史日期/时间禁用，确认前再次校验。
- 发送前汇总确认。

原型使用演示数据，不调用短信发送或计费接口；研发实现应以本文业务规则、服务端校验和验收用例为准。
