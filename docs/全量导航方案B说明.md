# 全量导航方案 B

新增独立入口 `prototype/navigation-mega.html`，不替换上一版 `prototype/index.html`。复用已有业务脚本、数据与样式，仅新增导航壳层。

- 全部功能：分类目录、多栏功能组、菜单搜索、收藏与最近访问；仅浏览分类不切换底下业务页面。
- 顶部导航：左侧依次为功能菜单图标、用友品牌、工作台；功能图标打开全量导航，右侧保留功能搜索和当前组织。
- 常规页面：保留单列当前模块导航，可收起。
- 全局三级菜单：营销触达 → 短信营销 → 短信任务 / 短信模板；客户与人群 → 意向评分配置 → 评分规则 / 行为权重 / 规则版本。页面内不重复展示同一套标签。
- 活动上下文导航：活动管理 → 具体活动 → 活动页面 / 报名设置 / 参会人员 / 签到与互动 / 直播 / 邀请与通知 / 线索与跟进 / 数据分析。先选活动才出现，侧栏明确当前活动名称；返回列表后撤去这些入口。
- 活动管理全局菜单按现有系统截图补齐：活动运营（活动专题、活动列表、活动分类）、统计分析（场次分析、人数分析、活动统计、机构统计、直播统计、定制报表）、其他管理（回收站）。全量面板分栏展示，活动列表侧栏按相同分组展示。
- 保留旧系统各统计名称，避免在未核实指标口径时合并统计功能。“统计分析”是全局统计入口分组，与具体活动内的“数据分析”区分。
- 列表状态与筛选标签继续保留在页面内，不一律提升到全局菜单。
- 原有 7 个功能以及新增的 9 个活动功能保持“仅菜单”，不创建业务页面。活动列表仍连接原有页面；点击仅菜单项只提示，不替换当前业务内容。
- 上一版仍保留在 `prototype/index.html`，方案 B 顶部不再放置评审性质的“对比上一版”入口。

# 2026-09-17 菜单一致性修订

方案 B 将独立管理功能统一置于左侧可展开分组：文章（列表、分类、模板、专题、公共文章池），资料/视频/海报（列表、分类），表单（列表、数据分析），落地页（列表、分类、内容模块），线索流转配置（总览、流转方式、MK分派规则、CRM同步配置、去重策略、运行记录）。短信任务与模板、意向评分配置沿用同样的分组方式。单一视图不增加层级。分组采用单开手风琴：默认仅展开当前功能所属分组，点击其他分组时自动收起原分组，也允许收起全部分组。

隐藏已迁移的内容页签、落地页页签和线索设置内层导航。发布范围、发送状态、线索处理状态、CRM配置细项和详情抽屉标签仍在页面内；活动报名与签到仍须进入具体活动后显示。全部功能、搜索、收藏、地址路由与左侧选中状态同步，缺失页面仍仅展示菜单。仅修改方案 B，复用已有业务视图。

验证：DOM 交互检查覆盖所有内容子视图、落地页分类、线索配置、历史后退、已有短信与活动导航及菜单占位行为。
