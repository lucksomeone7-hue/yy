# 互动抽奖界面优化

本次针对大屏管理、奖项和人数配置、抽奖形式、舞台主题及大量中奖结果进行优化，沿用原仓库的 HTML、CSS、原生 JavaScript 及用友品牌色。

## 入口与布局

- 管理员导航 → 活动列表 → 管理活动 → 互动抽奖。
- 签到与互动页面也可通过“管理互动抽奖”进入。
- 直接访问 `prototype/navigation-admin.html#activityDetail/lottery`，刷新可恢复该入口。
- 大屏管理与具体大屏详情分层；详情包含“奖项设置 / 抽奖池名单 / 中奖记录”。
- 详情顶部增加“设置奖项 → 准备名单 → 选择形式与主题”三步准备引导，显示剩余名额和可抽人数；没有可抽人员或剩余名额时不能启动。
- “选择形式并进入大屏”为主要操作，先打开独立启动设置，再进入舞台预览。启动设置支持幸运转盘、单人滚动、头像矩阵、砸金蛋、幸运老虎机、名单滚动、3D 球形，共七种形式。
- 展示舞台与控制台分区，可收起控制台或进入全屏；支持六套主题与减少动态效果。进入舞台不会自动开始或生成结果。
- 奖项卡片统一展示总名额、已抽、剩余、每轮默认人数及预计剩余轮数，新增入口缩为正常按钮及紧凑虚线卡。
- 空名单和空记录展示下一步引导，零结果不展示无意义分页。

## 后台完整操作流程

1. **新建大屏**：填写大屏名称，进入详情。奖项与名单可分别准备，不必一次完成所有设置。
2. **设置奖项**：填写奖项等级、奖品名称、总中奖名额和每轮默认抽取人数；总名额控制奖品数量，每轮人数控制现场节奏。
3. **准备名单**：按 CSV 模板导入姓名、公司、手机号，查看有效人数。已中奖人员自动排除后续所有奖项的抽取。
4. **选择抽奖形式与舞台**：点击主要操作，确认本轮奖项、人数、形式、主题和减少动态效果。摘要显示限制原因、本轮结束后的剩余名额及结果展示方式。
5. **进入舞台**：此时仍为准备态。可返回设置且保留配置；开始后循环，停止时才确认并保存本轮结果。循环与减速期间锁定配置及返回设置操作。
6. **查看本轮结果或继续下一轮**：根据中奖人数使用大卡、紧凑名单或分页结果。返回后台后，在“中奖记录”筛选和导出全部历史结果。

普通后台入口使用 `window.mkLottery.openSetup()` 打开启动设置；原有 `window.mkLottery.openDraw()` 和直接演示预览仍可直接进入舞台。

## 总名额与每轮人数

奖项的 `total` 是累计发出的总数量，范围为 1–10,000，编辑后不能少于已抽出数量。新增 `batchSize` 表示每轮默认人数，范围为 `1–min(50, total)`；此字段对旧记录可选，缺少时按总名额推导默认。

| 总中奖名额 | 推荐每轮默认人数 |
| --- | ---: |
| 1–5 人 | 1 人 |
| 6–20 人 | 5 人 |
| 21 人及以上 | 10 人 |

现场批量抽取建议每轮 10–20 人，最多 50 人；可以修改有效范围内的默认值。例如共 100 个名额、每轮默认 10 人，按默认预计 10 轮完成。实际本轮人数 `quantity` 可以单独调整，其上限为“形式上限、奖项剩余名额、当前可抽人数”的最小值。

转盘、单人滚动、金蛋每轮 1 人；老虎机每轮最多 3 人；矩阵、名单、球形每轮最多 50 人。默认 10 人的奖项切换到转盘后，仅将本轮限制为 1 人，不改写奖项默认；剩余不足默认人数时也只限制本轮，并显示原因。

系统共预置 **6 套主题**，与七种抽奖形式独立组合：

| 主题 | ID | 背景 |
| --- | --- | --- |
| 红金盛典 | `festival` | 系统渐层 |
| 深蓝星光 | `midnight` | 系统渐层 |
| 霓虹律动 | `neon` | 原始 JPG 图片 |
| 冰蓝会场 | `ice` | 原始 PNG 图片，浅底深字 |
| 红色庆典 | `celebration` | 原始 PNG 图片 |
| 曙光会场 | `dawn` | 原始 PNG 图片，浅底深字 |

四张原始图片保存在 `prototype/assets/lottery/themes/`，均为 1920 × 1080，未缩放或重新压缩，总计约 3.61 MiB。主题选择会同步改变卡片、姓名、辅助文字和焦点颜色，浅色主题采用深色文字。当前未提供自定义背景上传，也未新增奖品图片或人员照片上传。

## 大量中奖结果

- 本轮 1–5 人：以大头像卡突出展示，并保留已经停靠的抽奖画面。
- 本轮 6–10 人：使用紧凑卡片作为中奖名单主画面，不再让停止后的动画场景占据主要空间。
- 本轮 11–50 人：结果每页 10 人，显示本轮总人数、当前页与展示范围；50 人为 5 页。

结果冻结本轮提交时的顺序，翻页只切换展示，不改变人员、轮次、名额或中奖记录，不重新抽取。结果页标题明确标识“本轮中奖名单”，与后台全部历史记录区分。翻页事件使用 `lottery:effect-state`，包含 `reason: 'result-page'`、`resultPage`、`pageCount` 和 `winnerCount`。

## 抽奖动效与研发入口

- 直接打开 `prototype/lottery-preview.html`，自动进入抽奖舞台；普通管理入口仍保持原有路径。
- 新浏览器内置 64 位虚构参与人；旧记录保留，可通过“补齐内置示例人员”合并缺失示例，已导入名单和中奖记录继续保留。
- 七种形式共用奖项、名单与记录：开始仅运行视觉循环，停止时一次性生成并保存结果，再播放减速与揭晓。
- 滚动时关闭取消本轮，停止后关闭保留结果；中奖人员从后续所有奖项中排除，名额用尽后禁止继续抽取。
- 展示引擎与结果控制器独立。研发可查看 `prototype/lottery-motion-guide.html` 或 [完整动效与研发交接说明](./互动抽奖动效与研发交接.md)，包含各形式时序、缓动、四阶段状态、接口契约与验收清单。

## 原型边界

这是现有静态原型中的可交互演示。示例数据明确标识；修改保存在当前浏览器本地，未连接正式人员数据或抽奖服务，不跨设备同步。正式活动需要接入服务端名单、权限与抽奖结果存储。

新增样式使用 `lottery-` 前缀，仅在抽奖面板激活时隐藏活动概览。其他活动功能与原导航继续使用现有实现。

本次互动抽奖更新纳入 v2.2.0 发布范围，正式原型由 `main` 分支发布到 `/mk/`；版本号、Git Tag、GitHub Release 与历史归档遵循 `VERSIONING.md`。
