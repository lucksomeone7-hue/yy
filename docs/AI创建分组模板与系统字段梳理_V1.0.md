# AI 创建分组：模板与系统字段梳理

## 建议结论

首期预置 **6 个模板**，覆盖新客转销售、内容培育、活动回访、沉默召回和企业级信号。模板是自然语言示例和字段条件的快捷入口，不是固定规则；用户可编辑规则、预览人数后保存为现有条件组。

## 首期模板

| 模板 | 默认圈选条件 | 依赖系统字段 | 字段/数据缺失时 |
| --- | --- | --- | --- |
| 高意向但未进入 CRM | 意向分 ≥ 80；CRM 阶段为空/未建档；排除员工和无效客户 | `intent_score`、`intent_level`、`crm_customer_stage`、`user_scope`、推荐排除字段 | 不展示模板或明确标注“CRM 阶段数据未接入” |
| 方案页高频访问未留资 | 近 7 天方案页访问 ≥ 2 次；未提交有效表单 | 统一行为事件的时间、事件类型、页面/内容 ID；转化表单事件 | 若缺少表单提交事件，只生成“高频访问”模板并移除未留资条件 |
| 活动报名未签到 | 已报名且未签到；可选意向分阈值 | 活动 ID、报名状态、签到状态、事件时间；`intent_score` | 活动报名/签到数据未接入时，不提供模板 |
| 沉默高意向客户召回 | `intent_score` ≥ 80；最近 30 天无行为；排除拒绝触达和员工 | `intent_score`、`intent_level`、`last_active_time` 或 `rfm.recency_days`、行为排除字段 | 没有可靠最近活跃时间时，停用该模板，不用历史 `lifecycle` 替代 |
| 活动后活跃下降客户 | 参加/签到过活动；近 30 天行为较之前周期下降；可选行业/兴趣 | 活动行为事件；`last_active_time`、分周期行为次数；`behavior_tags` 或 `interest_tags` | 若无周期行为统计，退化为“参加活动且近 30 天无活跃”，并在解析说明中提示 |
| 多人活跃企业 | 近 7 天同一企业有有效行为的去重联系人 ≥ 3，且近 7 天产品/方案页访问 ≥ 1 次；企业意向分 ≥ 70 | `account_id`、联系人身份关联、近 7 天行为事件、企业联系人去重规则、产品/方案页事件、企业意向分；访问次数按企业汇总 | 企业归属、去重或行为事件不可靠时，不展示此模板；分组对象仍是联系人，不是企业账户 |

## 系统字段建议

### 一期可直接作为条件的现有/已定义字段

| 字段 | 用途 | 交互建议 |
| --- | --- | --- |
| `yht_id` | 用户唯一标识、去重 | 系统字段，不让运营配置 |
| `user_scope` | 区分员工、客户、伙伴、未知用户 | 默认只圈选 `customer`；员工默认排除 |
| `is_excluded_from_recommendation` | 排除不可经营人群 | 默认排除，并允许查看排除人数 |
| `exclude_reason` | 解释排除原因 | 预览阶段展示原因汇总 |
| `intent_score` | 意向分数范围 | 支持大于/小于/区间；范围 0–100 |
| `intent_level` | 高/中/低/沉默意向层级 | 用于快捷选择，与 `intent_score` 二选一或组合 |
| `behavior_tags` | 产品、行业、领域、角色、场景等行为兴趣 | 按标签组和值选择，避免输入自由文本 |
| `interest_tags` | 兴趣主题筛选 | 支持包含/不包含；展示标签来源 |
| `rfm.recency_days` | 最近活跃天数 | 用客观天数表达沉默，不用 `lifecycle` |
| `rfm.total_hits` | 行为命中次数 | 用于近周期活跃次数需按窗口聚合 |
| `crm_customer_stage` | CRM 客户阶段 | 统一阶段字典；未同步/跟进中/已转化等 |
| `generated_at` | 画像数据更新时间 | 显示数据新鲜度，不作为用户圈选条件 |

### 为完整支持模板需补齐/规范的数据字段

这些字段有些是事件数据或派生条件，不应仅为了原型直接宣称为现存字段。研发接入前需确认来源、字典和计算口径。

| 建议字段/事件 | 支持能力 | 口径要求 |
| --- | --- | --- |
| `last_active_time` | 最近活跃筛选 | 仅由有效行为事件计算；明确时区和数据延迟 |
| `behavior_count_7d`、`behavior_count_30d` | 活跃次数和趋势 | 统一有效行为集合；窗口按当前时间回溯 |
| `event_type`、`event_time`、`event_id`、`content_id/page_id` | 页面访问、下载、报名、签到、表单提交 | 事件名统一、可去重、保留发生时间 |
| `activity_registration_status`、`activity_checkin_status` | 活动报名和签到模板 | 说明取消报名、补签、重复报名的规则 |
| `account_id` | 多人活跃企业 | 需身份合并、企业归属置信度及匿名用户处理规则 |
| `crm_record_type`、`crm_record_id`、`sales_owner_id` | CRM 样本和状态分流 | Lead/Contact/Account 匹配优先级与状态映射需统一 |
| `marketing_consent`、`channel_consent` | 评估后续触达资格 | 仅在经营动作阶段使用；建组本身不触达 |

## 公共默认条件与保存约定

- 默认排除 `user_scope = internal_employee`、无效/测试用户，以及 `is_excluded_from_recommendation = true` 的用户；展示命中数量和主要原因。
- 模板解析后先显示条件、数据更新时间和预计人数；用户确认结果后才允许创建。
- 数据字段不可用时，明确告知原因并移除依赖条件；不可静默扩大人群范围。
- 保存为现有 `group_type = condition` 用户分组，记录 `create_method = ai` 和 `rule_detail`；AI 不另建分组体系。
- 建组只保存圈选规则；消息发送、CRM 写入、创建线索等动作需要独立确认。
- `lead_grade`、历史 `active_score` 和 `lifecycle` 不作为新模板的经营筛选字段。

## 与原型模板的对应

当前原型已有 6 个入口：高意向未进入 CRM、方案页访问未留资、活动报名未签到、活动后活跃下降、多人活跃企业、沉默高意向客户。上述梳理明确了各模板依赖的数据，并标出尚需研发确认的事件字段和身份关联能力。
