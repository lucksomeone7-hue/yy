# 列表筛选与交互统一规范 V1.0

## 1. 目的与适用范围

本规范用于 Marketing Cloud 桌面端的列表、管理类页面，统一筛选、搜索、重置、高级筛选、结果反馈和表格布局。适用于落地页管理、模块管理、短信管理、用户列表及后续同类页面。

目标是让用户在任一列表页都能快速判断：数据来自哪里、当前条件何时生效、结果受哪些条件影响，以及无结果时如何恢复。

## 2. 基本原则

1. **同一概念同一名称、同一位置、同一行为。** 发布范围、搜索、重置和高级筛选不得在不同页面使用不同口径或交互方式。
2. **筛选条件以一次查询为单位生效。** 页面提供“搜索”或“查询”按钮时，用户设置的条件应在点击按钮或关键词框按 Enter 后统一应用。
3. **业务优先于筛选。** 新建、发送等页面主操作放在标题区右上；筛选区控制在必要高度，首屏优先呈现结果和主要操作。
4. **当前状态可见、可恢复。** 结果数量、已生效条件和无结果恢复入口必须明确，不让用户猜测系统当前用了哪些条件。
5. **权限不由前端筛选放大。** 发布范围只在用户已有数据权限内切换；服务端始终负责最终权限判断。

## 3. 术语与统一口径

### 3.1 发布范围

涉及内容归属的页面统一使用“发布范围”，选项和含义固定如下：

| 选项 | 含义 |
| --- | --- |
| 全部 | 当前用户有权限查看的全部记录。 |
| 本人发布 | 当前登录用户发布的记录。 |
| 所在组织发布 | 当前登录用户所在组织发布的记录，**包含本人发布**。 |
| 其他组织发布 | 不属于当前登录用户所在组织、但当前用户有权限查看的记录。 |

不得再使用“数据范围”“机构”“所在组织”“其他组织”等作为同一筛选维度的页面文案。落地页管理、模块管理、短信管理应遵循上述口径；若短信模板没有“发布”概念，可在字段说明中保留“发布人 / 所属组织”，筛选仍使用“发布范围”。

### 3.2 搜索、查询与重置

- 以标题、名称、地址、发布人等文本检索为主的列表，按钮文案使用“搜索”。
- 以时间、指标、意向等分析条件为主的页面，可使用“查询”。同一页面不可同时出现两个含义相同的提交按钮。
- 清除当前页面全部筛选条件并恢复默认状态的按钮统一使用“重置”。不得使用“清空”“恢复”替代。
- 无结果状态中的恢复入口使用“清空筛选”，避免与普通重置按钮混淆。

## 4. 筛选区布局

### 4.1 有发布范围的管理页

按两行组织，阅读和操作顺序固定：

```text
第 1 行：发布范围  [全部] [本人发布] [所在组织发布] [其他组织发布]
第 2 行：关键词 / 常用下拉条件 → 搜索 → 高级筛选（如有）→ 重置
```

- “发布范围”置于筛选卡片第一行左侧，选项采用同一组横向标签按钮。
- 第二行从左到右先放输入和下拉条件，再放执行和恢复操作。
- 搜索按钮紧跟最后一个常用条件；高级筛选和重置位于其右侧。
- 高级条件默认收起，不应挤占首屏表格区域。

### 4.2 无发布范围的管理页

用户列表等没有内容归属概念的页面使用单行：

```text
关键词 → 常用下拉条件 → 搜索 → 重置
```

不要为形式统一而补充无业务含义的“发布范围”。

### 4.3 常用与高级条件的划分

以下条件属于常用条件，应默认展示：关键词、类型、身份、状态、时间范围，以及用户高频使用的一个业务维度。

其余低频或组合使用的维度放入高级筛选，例如所属组织、行业、产品、地域、域名、来源等。高级筛选只在确有隐藏条件时出现；只有两三个常用条件的页面不必为了统一而增加入口。

## 5. 控件与状态规范

### 5.1 按钮

| 控件 | 视觉与位置 | 行为 |
| --- | --- | --- |
| 搜索 / 查询 | 红色主按钮，位于常用条件之后 | 应用当前全部筛选条件；关键词框按 Enter 与点击效果相同。 |
| 重置 | 描边次按钮，位于筛选行最右 | 恢复页面默认筛选、收起高级筛选、回到第一页并重新查询。 |
| 高级筛选 | 描边次按钮，位于搜索之后、重置之前 | 收起时为“高级筛选⌄”，展开时为“收起筛选⌃”。 |
| 页面主操作 | 红色主按钮，位于标题区右上，如“新建落地页”“发送短信” | 打开创建或发送流程，不与筛选按钮混排。 |

同一行可同时有页面主操作和搜索主按钮：前者服务创建任务，后者服务当前筛选任务，必须分别放在标题区和筛选区。

### 5.2 条件生效与保留

- 页面有搜索/查询按钮时，输入、下拉和高级条件在执行搜索/查询后生效；切换页面、收起高级筛选时保留已输入或已应用的值。
- 发布范围可作为快捷范围切换立即生效；立即生效时必须同时保留其余已应用条件，不能静默丢失用户已设置的条件。
- 重新查询、切换发布范围、重置条件后，分页回到第一页。
- 筛选改变结果集时，默认清除当前列表的勾选项，防止用户对不可见记录执行批量操作。

### 5.3 已选条件回显

执行筛选后，在筛选区下方或结果标题旁展示：

- 结果数量，例如“6 个落地页”“符合条件 12 条”；
- 已生效的非默认条件标签，例如“发布范围：本人发布”“状态：已启用”；
- 高级筛选收起后，已生效的高级条件仍必须可见。

条件标签应支持单项移除；移除后立即按剩余条件刷新结果。默认值（如“全部”）不必重复显示为条件标签。

## 6. 结果、空状态与异常状态

### 6.1 筛选无结果

筛选没有命中时，表格位置展示空状态，不保留一片无说明的空白区域。空状态包含：

1. 明确标题，如“没有符合条件的落地页”；
2. 简短恢复提示，如“请调整发布范围或关键词后重试”；
3. “清空筛选”按钮，恢复默认筛选并重新查询。

筛选无结果与“尚未创建任何记录”应使用不同文案：前者提供清空筛选，后者提供“新建”或“创建”入口。

### 6.2 其他状态

加载中、接口错误、无查看权限和无数据分别表达，不能都显示为“暂无数据”。错误状态提供重试；无权限状态说明无法查看的范围；加载状态保留表格骨架，避免页面跳动。

## 7. 表格与列表布局

1. 标题、核心业务信息、状态和操作按阅读优先级排列；名称/标题通常在最左，操作在最右。
2. 宽表格的名称列和操作列可固定，保证横向滚动时仍能识别记录并完成操作。
3. 状态使用统一颜色和文字，不只依赖颜色传递含义。
4. 筛选卡片与结果表格之间保留明确间距；筛选区不应因高级条件常驻而压缩首屏结果。
5. 在 1280、1440、1920px 宽度下检查：筛选控件不换行遮挡、操作列可见、长文本有截断或换行策略。

## 8. 页面落地映射

| 页面 | 第一行 | 第二行常用条件 | 高级条件 / 补充规则 |
| --- | --- | --- | --- |
| 落地页管理 | 发布范围 | 字段选择、关键词、搜索、重置 | 所属组织、分类、状态、产品、行业、域名放入高级筛选；展示已选条件。 |
| 模块管理 | 发布范围 | 模块名称、类型、来源、搜索、重置 | 当前常用条件已足够时不展示高级筛选。 |
| 短信管理 | 发布范围 | 模板标题、短信类型、搜索、重置 | “已发送 / 定时发送”等业务状态使用结果区页签，不与发布范围混淆。 |
| 用户列表 | 无 | 姓名/手机号/邮箱/所属企业、身份、用户状态、搜索、重置 | 无发布范围；筛选无结果时提供清空筛选。 |
| 意向与运营分析页 | 视业务是否有归属范围决定 | 时间、意向、行业、地域等，使用“查询” | 自定义时间范围在选择完整起止日期后再可查询；结果与指标同步刷新。 |

## 9. 验收清单

| 检查项 | 验收要求 |
| --- | --- |
| 术语 | 同一业务范围均为“发布范围”，四个选项名称和含义一致。 |
| 按钮 | 搜索/查询为红色主按钮；重置为描边按钮；高级筛选名称与展开状态一致。 |
| 顺序 | 有范围页按“范围 → 条件 → 搜索 → 高级筛选 → 重置”；无范围页按“条件 → 搜索 → 重置”。 |
| 生效 | Enter 与搜索一致；条件生效时机明确；切换范围不丢失其他已应用条件。 |
| 回显 | 查询后能看到结果数和所有非默认已选条件，高级条件收起后仍可识别。 |
| 重置 | 恢复默认条件、清空列表勾选、回到第一页，并重新加载结果。 |
| 空状态 | 过滤无结果、完全无数据、加载失败和无权限可区分，且均有合适的下一步。 |
| 布局 | 主要操作在标题区；筛选不挤占首屏；宽表格操作列可访问。 |

## 10. 维护规则

新增管理页或调整现有筛选时，先按本规范确定筛选维度、默认值、结果回显和空状态，再进入视觉设计和开发。若业务确需偏离本规范，应在页面 PRD 中写明偏离原因、目标用户和验收方式，并同步更新本规范版本。
