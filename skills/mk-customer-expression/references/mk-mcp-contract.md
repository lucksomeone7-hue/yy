# mk-mcp接口适配清单

状态：工具名称、职责和两步调用协议来自用户提供的信息；真实参数schema和返回对象尚未提供。本文不是可直接执行的接口参数示例，不应将内部逻辑字段伪装成已支持参数。

## 首次联调需要确认

| 项目 | 需要的证据 | 未确认时处理 |
| --- | --- | --- |
| auth_status | 实际schema及授权成功含义 | 不猜参数，不执行批处理 |
| listLead分页 | 请求参数、列表路径、结束标记、稳定排序 | 不猜page/pageSize等名称 |
| 范围与资格 | 组织、表单、时间筛选及入线索中心／启用依据 | 不能默认所有返回记录均可处理 |
| 记录主键 | 表单提交ID与线索ID的实际字段及关系 | 不用customer_id代替提交ID |
| 完整问答 | 题目、答案、选项映射、表单版本及完整性标记 | 不根据截断列表项生成 |
| 最新完整对象 | listLead是否完整、是否支持按ID筛选 | 两工具无法取得时需提供读取能力 |
| 摘要目标字段 | 实际字段名、类型和最大长度 | 不假定叫summary或description |
| save模式 | 局部更新或完整对象、必填／只读、null和省略语义 | 不尝试仅ID加猜测摘要字段 |
| 并发与幂等 | 版本条件、锁、持久任务ID及冲突响应 | 不能承诺全量任务安全重放 |
| 保存成功 | 业务成功字段、错误含义、读回一致性 | 模糊结果标unknown |
| 无内容 | MK存储方式及CRM排除逻辑 | 跳过save并记录no_content |
| CRM后续 | MK保存后可靠触发／扫描更新的服务 | 不声称save等于CRM成功 |

## 接入流程示意

```text
YonWork指定范围和批量
  → ToolSearch(auth_status) → DeferExecuteTool(auth_status)
  → ToolSearch(listLead) → DeferExecuteTool(listLead)
  → 资格、完整性、版本与去重检查
  → 摘要规则生成summary → 自动校验
  → 重新读取最新完整对象 → 版本比较
  → 按save契约构造最小允许变更
  → ToolSearch(save) → DeferExecuteTool(save)
  → 确认业务结果／必要时读回
  → 记录单条状态 → 下一条／下一页
  → 报告已确认回写与异常
```

每个重复读取、读回或翻页同样必须先ToolSearch再DeferExecuteTool。此示意不代表已有真实工具调用或端到端验证。

## 最小联调验收

1. 授权有效后加载真实schema，分页能按限定范围结束。
2. 一条有否定和条件的问答生成忠实摘要，准确回写原记录，其他字段逐项保持不变。
3. 列表对象缺字段或主键不明确时没有发生save调用。
4. 问答版本在生成后改变时不回写旧摘要；并发冲突按服务契约处理。
5. save响应丢失后先读回；结果不明不盲重试，不误报成功。
6. 写入影响列表过滤条件时仍不漏项，不重复处理已确认任务。
7. 空结果不覆盖有效表达、不写CRM；无内容契约不完整时跳过回写。
8. ToolSearch not found仅重试一次后提示重连，不绕过连接器。

真实联调需提供两个业务工具的schema和一条脱敏完整返回对象。若列表不返回完整对象，还需明确可用读取能力。本次只更新Skill说明，未访问或修改实际MK客户数据。
