LOTTERY / INTERACTION SPECIFICATION

互动抽奖
动效与研发说明

从创建大屏、奖项和名单准备，到选择形式、主题与本轮人数，再进入舞台。这里集中说明可点击流程、动效节奏、大批量结果和研发接口，便于设计、前端、后端与测试对齐。

01

后台准备与人数配置

新建大屏后，按详情顶部三步引导完成准备。奖项、名单可分别保存；没有可抽人员或剩余名额时，启动入口不可用。

01 / 奖项设置数量与节奏

添加奖品、总中奖名额、每轮默认人数。总名额控制累计发出的数量。

02 / 名单准备参与人员

按 CSV 模板导入姓名、公司、手机号；已中奖人员自动排除后续抽取。

03 / 启动设置选择形式与主题

确认奖项、本轮人数、形式、主题，预览摘要后进入舞台。

进入舞台只预览，不抽取。 点击“开始”才循环，点击“停止”才确定本轮结果。舞台准备与已揭晓时可返回设置，并保留配置；循环和减速期间锁定设置。

总名额、每轮默认、本轮人数是三个字段

prize.total 为累计总名额，范围 1–10,000；prize.batchSize 为每轮默认人数，范围 1–min(50, total)；quantity 为本轮实际人数。旧记录可缺少 batchSize，按下表推导。

推荐默认值可修改；实际本轮上限仍受形式、剩余名额和可抽人数共同约束。
总中奖名额推荐每轮默认人数节奏建议
1–5 人1 人少量奖项逐位揭晓
6–20 人5 人分轮抽取，保持现场节奏
21 人及以上10 人批量可按需调整至 10–20 人，每轮最多 50 人

例如共 100 个名额、每轮默认 10 人，按默认预计 10 轮。切换转盘后本轮上限为 1 人，或只剩 3 个名额时本轮受限，均只调整本轮，不把奖项默认值写回成 1 或 3。设置页显示约束原因和本轮结束后的剩余名额。

03

四阶段状态与提交边界

业务状态由控制器管理；展示引擎对应阶段为 idle → running → revealing → complete。

01 / IDLE准备就绪

选择样式、主题、奖项与人数。此时没有本轮结果。

02 / RUNNING视觉循环

开始只播放动效，锁定本轮配置，等待停止。

03 / SETTLING提交 · 减速揭晓

停止先确定并保存结果一次，再把结果传给动效。

04 / REVEALED本轮已揭晓

显示固定中奖名单，更新名额，可开启下一轮。

有效的停止动作，就是本轮结果的提交边界。 动画完成、翻牌、光点高亮和 transitionend 均不能再次写入记录。

循环期间关闭

结束本轮视觉，不新增中奖记录，不占用名额。重新打开后从剩余名单重新准备。

停止后、减速期间关闭

保留已提交的中奖记录。销毁动画不会撤销结果，也不能在重新打开时再次抽取同一轮。

本地保存失败时，结果仍在当前页面内存中生效，必须提示及时导出。不要把“动画已结束”等同于“结果已持久化”。同一大屏的中奖人从后续所有奖项中排除。

04

本轮结果与六套主题

引擎冻结本轮已提交人员及顺序。所有形式使用同一套结果规则；这里的“本轮中奖名单”与后台全部历史中奖记录分别展示。

分页为纯展示操作，不能触发开始、停止、抽取或写入记录。
本轮人数结果布局展示与操作
1–5 人hero 大头像卡保留抽奖停靠画面，完整展示本轮人员，无分页。
6–10 人compact 紧凑主结果隐藏停靠场景，主画面突出中奖名单，无分页。
11–50 人paged 每页 10 人显示上一页、下一页、展示范围和本轮总人数；50 人固定 5 页。

50 人结果第一页展示 1–10 / 50 人，第五页为 41–50 / 50 人；往返翻页保持顺序、轮次和名额。事件为 lottery:effect-state，附 { reason: 'result-page', resultPage, pageCount, winnerCount }，展示阶段仍为 complete。已提交记录始终可在后台筛选和导出。

05

展示引擎接口

activity-lottery.js 管理结果与本地存储，activity-lottery-effects.js 只负责表现，样式位于对应 CSS 文件。以下是接口调用顺序示意，controller 与 confirmedRound 由接入方提供。

const engine = window.MKLotteryEffects.create({
  host, mode, people, history, prize, quantity, reducedMotion,
  onRequestStart: () => controller.start(),
  onRequestStop: () => controller.stop()
});

// 开始：冻结本轮配置，只启动视觉循环。
engine.reset({ people, history, prize, quantity, reducedMotion });
engine.start();

// 停止：控制器先确认并提交结果，再交给引擎展示。
await engine.reveal(confirmedRound.winners);

// 关闭：清理 RAF / 定时器，结束未完成的 reveal 等待。
engine.destroy();

create(options)

创建指定形式。主题由容器 data-theme 控制；六套预置元信息见 MKLotteryThemes.items。

reset(next)

取消旧任务，更新可抽名单、奖项、历史和人数快照，回到准备态；不改中奖记录。

reveal(winners) → Promise

仅展示已确认结果。重复调用复用同一未完成 Promise；完成不代表再次提交。

destroy()

取消 RAF、计时器并结束等待。调用后的回调仍须检查会话是否已经关闭或被替换。

控制器向大屏派发 lottery:round-state：{ phase, mode, roundId }；引擎派发 lottery:effect-state 供观察展示阶段。事件只用于调试和测试，不能触发结果写入。

普通后台先用 window.mkLottery.openSetup() 打开启动设置，再确认进入舞台；window.mkLottery.openDraw() 保留直接进入能力。本页“查看原型”也直接进入舞台，便于演示效果。

RAF 减速采用“名义时长 + 5000ms”看门狗。后台暂停后，仍有效的会话会直接到达同一固定结果的精确终点，避免已提交轮次悬挂。

06

07

操作与验收要点

Space 在舞台普通区域开始 / 停止；控件聚焦时保留原生行为。F 切换全屏，Esc 退出 / 返回；浏览器全屏下先遵循浏览器的退出逻辑。控制区可收起，结果仍持续展示。

  • 七种形式均可开始、停止、揭晓；画面与记录的获奖人完全一致。
  • 本轮人数不超过模式上限、剩余名额与可抽人数；同人跨奖项不重复。
  • 连点按钮、连续空格或砸蛋与停止同时触发，只提交一次。
  • 循环时关闭不提交；减速时关闭保留结果；重开不受旧回调影响。
  • 标准与减少动态效果使用相同结果路径；无持续旋转、滚动和碎片。
  • 全屏进入 / 退出与控制区收起，不改变进度或遮挡关键操作。
  • 创建大屏、配置奖项、导入名单、选择形式主题后，进入舞台仍未抽取。
  • 默认人数缺省兼容旧数据；切换形式或剩余人数不足不改写奖项默认。
  • 分别验证 5 / 6 / 10 / 11 / 50 人；50 人结果为 5 页，每页 10 人。
  • 往返翻页没有遗漏、重复或顺序变化；记录数、名额与轮次保持不变。
  • 六套主题均可搭配七种形式；浅色背景姓名及分页按钮清晰可读。
  • 仅准备与已揭晓时可返回设置，草稿保留；循环和减速期间锁定。

全屏实际对大屏内部的 .lottery-modal-form 调用 requestFullscreen()，包含舞台与控制台。上述条目为验收清单，具体浏览器验证记录以交付说明为准。

默认演示使用虚构人员。旧浏览器记录会保留；“补齐内置示例人员”只合并缺失人员，保留已导入的名单，合并总数可以超过 64 人，不会重置已中奖状态。
